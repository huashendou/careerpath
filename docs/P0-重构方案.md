## 五、匹配口径（core-only 平移，证据不进分数）

```
required_score = Σ_required(W × M) / Σ_required(W) × 100，  M = min(L, T) / T   （上限 1）
bonus_score    = Σ_bonus(W × M)    / Σ_bonus(W)    × 100， 同上
evidence_coverage = 已挂证据的 required 技能数 / required 技能总数 × 100   ← 独立展示，不进上面两式
```

- **与《整体介绍》第十节公式等价**：文档写 `Match = Σ(W×Mi)/ΣW`，其中 `Mi` 是「掌握程度归一化后
  的比例」。取 `Mi = min(L,T)/T` 时两式数学上完全相同；此处选分母写法，是因为它能直接给出
  `numerator`/`denominator` 供界面核对「分母不是 100」。
- **必备与加分分开出分**，不合并成一个总分（《整体介绍》第十节 2）。加分项**不进必备项的分母**。
- **证据只独立展示（2026-11-15 用户裁决）**：不上传材料不扣分。理由与「加分项进分母」是同一种错误——
  把「没有也不影响胜任」的东西变成「没有就降分」。缺口项标 `hasEvidence`，界面单独给「缺证据」标签。
- `L_eff = max(自身, anyOf 成员)`，该要求只出一条记录；空维度返回 `null` 不返回 0。
- 分数只作辅助分析，UI 必须同时给出「为什么」：命中项、缺口项、缺证据项、Top 3 优先补强。
- 权重 `W` 与 `target_level` 由 JD 解析 + 用户人工修正产生，必须可追溯；`algorithm_version` 写入报告。

## 十、v1 资产与 v2 的关系

- v1 的 `dev` 分支停在 R1「有条件通过」，**不再合并 main**，作为历史基线保留。
- v1 已通过的算分口径（core-only、anyOf、空轴 null）作为 v2 匹配算法的**回归参照**：v2 必须能解释为什么同一画像在 v1/v2 下分数不同。
- v1 的评审记录与问题（重复 skillId→500、旧进程自测）在 v2 重写时不得复现。
