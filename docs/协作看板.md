## 二、Git 工作流

| 分支 | 用途 | 说明 |
|---|---|---|
| `main` | 已验收基线 | **只有 Trae 评审通过后才能合入**；任何时刻必须可运行 |
| `dev` | WorkBuddy 开发 | 全部开发提交在此；评审不通过原地修，不新建分支 |

**WorkBuddy 开工前**：

```bash
git status          # 必须干净
git switch dev
```

**WorkBuddy 收工前**：`git add` 具体文件 → `git commit`。提交信息前缀：`feat:` / `fix:` / `test:` / `style:` / `docs:` / `chore:`，示例 `feat: 岗位只读接口与 seed 脚本`。

**Trae 评审流程**：

```powershell
git switch dev
git log main..dev --oneline     # 看这一轮交付了哪些提交
git diff main...dev --stat      # 看改动范围
# 跑测试 / 启服务验证，结论写入 docs/评审记录.md
git switch main && git merge --ff-only dev   # 仅在全部阻断项修复后
git switch dev && git merge --ff-only main   # 保持 dev 不落后
```

**铁律**：
- `main` 出现未评审代码 = 流程违规，必须回滚。
- 阻塞项（P0）未清零不得合入；建议项（P1）可留到下阶段。
- 谁合并谁负责跑通一遍启动命令，不接受「代码看起来没问题」。
- 禁止 `git checkout --`、`git reset --hard` 覆盖对方成果。

## 三、接口契约（v2 · c3.2，生效）

> 适用：`backend-java`（对外，`/api`）+ `analysis-service`（对内，`/internal`）。前端只访问 Java，**不得直连 Python**。

### 3.0 通用约定

| 项 | 约定 |
|---|---|
| 服务与端口 | Java `http://127.0.0.1:8080`，前缀 `/api`；Python `http://127.0.0.1:8000`，前缀 `/internal`，仅内网；前端 `http://127.0.0.1:5173`，`/api` 代理到 8080 |
| 字段命名 | **JSON 一律 camelCase**，两种语言都不得返回 snake_case |
| 鉴权 | `Authorization: Bearer <accessToken>`。免鉴权白名单仅三项：`POST /api/auth/register`、`POST /api/auth/login`、`GET /api/health` |
| 时间 | ISO 8601，UTC，带 `Z`，如 `2026-11-15T08:30:00Z`；纯日期字段为 `YYYY-MM-DD` |
| 成功响应 | **直接返回资源对象**，不包 `code/data` 封套 |
| 列表响应 | 不分页：`{"items":[...]}`；分页：`{"items":[...],"total":37,"page":1,"size":20}` |
| 分页参数 | `page` 从 1 开始默认 1；`size` 默认 20、上限 200，越界按上限截断 |
| 错误响应 | HTTP 4xx/5xx + `{"detail":{"code":"USERNAME_TAKEN","message":"用户名已存在"}}` |
| 空值语义 | **「不适用」用 `null`，不是 0**：某侧无要求时该侧分数为 `null` 并在 `status` 说明。禁止 0 代 null、禁止除零 |
| 链路追踪 | 可带 `X-Trace-Id`，服务原样回写并在日志标注；Java→Python 透传同一值 |
| 越权语义 | 访问他人资源返回 **404**（不暴露存在性），不返回 403 |

### 3.1 认证与个人档案（模块 1，T1）

**POST `/api/auth/register`** → `201`

```json
// 请求
{ "username": "student01", "password": "123456" }
// 响应
{ "accessToken": "eyJhbGciOi...", "tokenType": "bearer", "expiresIn": 86400,
```

规则：用户名 3–32 位字母数字下划线、密码 6–64 位（`422 VALIDATION_ERROR`）；重复用户名 `409 USERNAME_TAKEN`（由数据库唯一索引兜底，不只靠应用层查重）。

### 3.5 匹配与差距（模块 6，T4）

**POST `/api/match/{jobId}`** —— 取当前用户的画像算分，并落库一份结果

```json
{
  "jobPositionId": 12, "jobTitle": "Java 后端开发实习生", "status": "ok",
  "requiredScore": 41.1765,
  "bonusScore": 66.6667,
  "numerator": 105, "denominator": 255,
  "bonusNumerator": 10, "bonusDenominator": 15,
  "evidenceCoverage": 42.0,
  "counts": { "requiredMastered": 2, "requiredWeak": 3, "requiredMissing": 3, "requiredTotal": 8,
              "bonusMastered": 1, "bonusPending": 2, "evidenceCovered": 2 },
  "gaps": [ { "skillId": "spring-boot", "skillName": "Spring Boot", "dim": "stack",
              "weight": 2, "target": 3, "level": 1, "effectiveLevel": 1,
              "gap": 2, "priority": 4, "status": "weak",
              "hasEvidence": false, "evidenceStrength": 0 } ],
  "topActions": [ "spring-boot", "sql-query", "redis" ],
  "bonusItems": [ { "skillId": "docker", "skillName": "Docker", "dim": "engineering",
                    "weight": 1, "target": 2, "level": 2, "status": "mastered" } ],
  "radar": { "axes": [ { "dim": "foundation", "name": "编程基础", "target": 3.2, "current": 2.8,
                         "hasCore": true, "coreWeight": 9 },
                       { "dim": "data", "name": "数据与存储", "target": null, "current": null,
                         "hasCore": false, "coreWeight": 0 } ],
             "dataAxisCount": 5 },
  "meta": { "scoringVersion": "v2.0-required-only", "displayBadge": "示例数据 v0.1", "disclaimer": "…" }
}
```

| 字段 | 规则（与 AGENTS.md 第七节一致，不得改） |
|---|---|
| `requiredScore` | `Σ_required(W×min(L,T)) / Σ_required(W×T) × 100`，**4 位小数**；无必备要求 → `null` + `status=NO_REQUIRED_REQUIREMENT`，不得返回 0、不得除零 |
| `bonusScore` | `Σ_bonus(W×min(L,T)) / Σ_bonus(W×T) × 100`，4 位小数；无加分要求 → `null`。**与必备分分开，不存在总分字段**。`EMPTY_PROFILE` 时同为 `null`（没自评 ≠ 拿了 0 分） |
| `numerator` / `denominator` | 必备分的分子分母原样暴露，评审可直接核对「分母不是 100」 |
| `status` | `ok` \| `NO_REQUIRED_REQUIREMENT` \| `EMPTY_PROFILE`（未做任何自评：`requiredScore` 与 `bonusScore` **同为 `null`**，界面提示「尚未完成自评」，**不得显示 0%**） |
| `counts` | `required*` 只统计必备项，`bonus*` 只统计加分项，**两者不相加** |
| `gaps` | 只收 `gap = max(T−L_eff, 0) > 0` 的必备项，按 `priority = W×gap` 降序；`status` 只有 `missing`(L_eff=0) 与 `weak` 两态；已掌握不进列表 |
| `effectiveLevel` | `anyOf` 命中时 `L_eff = max(自身, 成员)`；该要求只出一条，成员不得独立出现；`level` 与 `effectiveLevel` 同时返回 |
| `hasEvidence` | 该技能是否挂有证据；**只做标记，不改分数** |
| `topActions` | `gaps` 前 3 个 `skillId`，不足按实际数量 |
| `bonusItems` | 只有 `mastered` / `pending` 两态，不参与任何百分比 |
| `radar.axes` | **恒定 6 条**；`target = Σ(W×T)/Σ(W)`、`current = Σ(W×min(L,T))/Σ(W)`；无必备要求的维度 `target/current=null`、`hasCore=false`、`coreWeight=0`，**禁止 0 代 null** |
| `evidenceCoverage` | 有证据的必备技能数 / 必备技能总数 × 100，独立展示，**不参与分数** |

### 3.8 Java → Python 内部接口

**硬约束**：只有 Java 调用；路径 `/internal`；必带 `X-Internal-Token`（与根 `.env` 的 `INTERNAL_TOKEN` 一致），可选 `X-Trace-Id`；超时 1500ms；**Python 不写任何业务表**。

**GET `/internal/health`**（已实现）

```json

  "time": "2026-11-15T08:57:48Z",
  "dictionary": { "loaded": true, "version": "v0.1", "categoryCount": 6, "skillCount": 61 } }
```

令牌缺失/错误 → `401 {"detail":{"code":"INTERNAL_UNAUTHORIZED",...}}`。

**POST `/internal/parse/jd`**（已实现）

```json
// 请求
{ "text": "……JD 原文……", "jobTitle": "Java 后端开发实习生", "source": "手动粘贴" }
// 200 —— requirements 字段与 3.3 的解析响应一致
{ "requirements": [ … ], "conditions": { "education": "本科及以上", "experience": "1-3 年" },
  "matchedCount": 3, "requiredCount": 2, "bonusCount": 1,
  "algorithmVersion": "jd-rule-v1.0", "dictionaryVersion": "v0.1", "disclaimer": "…" }
```

解析规则：技能词典 + 同义词 + 正则；英文别名**长度倒序 + 词边界**、中文按子串、命中区间遮蔽；必备/加分按**分句**判定；结果只作预填。

**必须显式传 `--server.port=8080`**：本机直接 `mvn spring-boot:run` 会被环境变量顶成随机高位端口
